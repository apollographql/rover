Rover doesn't collect any personally identifiable information such as API keys, graph names, or file paths. 

By default, Rover collects some anonymous usage data to help Apollo improve the tool. To opt out of data collection, use any of the following:

- Set the `APOLLO_TELEMETRY_DISABLED` environment variable in each environment where you use Rover. Any value disables telemetry, including `false` or an empty value.
- Pass `--telemetry-disabled` to a command.
- Store the setting on a profile with `rover config set APOLLO_TELEMETRY_DISABLED true`. It applies whenever Rover uses that profile.
- Add `APOLLO_TELEMETRY_DISABLED: true` under `settings:` in your project's `.rover/rover.yaml`, to opt out for everyone who runs Rover in the project.

In a profile or the project file, the value is a real boolean, so `false` there keeps telemetry enabled. See [Configuring Rover](/rover/configuring#boolean-values) for how Rover reads each source and which one takes priority.

## Collected data

Unless you opt out, Rover reports the following data each time you run a command:

- The command that was run, and the names of the flags it was run with, but never their values, except for the value of `--format`. Positional arguments, such as file paths, graph refs, and profile names, are not reported.
- The version of `rover` that was executed
- A unique, anonymized **machine identifier**, which is the same for every command run on the same machine
- A unique, anonymized **session identifier**, which is different for every command
- The SHA-256 hash of the directory that `rover` was executed from
- The SHA-256 hash of the Git remote URL of the repository where you executed `rover`, if any
- The operating system `rover` was executed on
- The CPU architecture `rover` was executed on
- The CI system `rover` was executed on, if any
- How long the command ran, in milliseconds, including writing its output (Rover 1.1.0 and later). It is left out when a signal stopped the command.
- How the command ended (Rover 1.1.0 and later): `success`, `user_error`, `internal_error`, `connection_error`, or `terminated`. It carries no error message or detail.
- Whether the invocation looks `automated` (CI was detected, or standard input isn't a terminal) or `interactive` (Rover 1.1.0 and later). It carries no hostname, username, or path.
- A one-way identifier of the graph the command ran against, if it has a graph ref (Rover 1.1.0 and later). Rover derives it from the graph ref and a random value it generates on first use and stores in `install_salt.txt` beside `machine.txt`, and never sends. It can't be reproduced by hashing known graph refs, and it groups invocations from one install only. Deleting `install_salt.txt` resets it. Commands without a graph ref send no identifier.

Rover never sends an account, organization, or user identifier.

For more information on the data Apollo collects, see [our privacy policy](https://www.apollographql.com/Apollo-Privacy-Policy.pdf).
